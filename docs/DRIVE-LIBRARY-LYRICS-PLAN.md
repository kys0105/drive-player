# Google Driveのフォルダ選択・共有歌詞：実装方針

作成日：2026-10-28。**実装前の提案**。この文書の作成段階では、Driveの移動、歌詞のアップロード、アプリコードの変更、本番反映は行っていない。

## 1. 今回の到達点

- `00_試聴用` をアプリの公開対象ルートにし、その直下のフォルダを選んで聴けるようにする。
- 最初のフォルダを `3rd album` とし、現在の10曲を移す。
- Notionにある歌詞をUTF-8のLRCへ変換し、音源とともにGoogle Driveで管理する。初回のタイミングは仮でよい。
- 歌詞画面で「追従」「全文」を切り替える。
- 現行のスマホ向けUI、選択した曲の端末保存、30日間のオフライン利用を引き継ぐ。

## 2. 確認できたことと未確認事項

### 音源

ローカルのGoogle Drive同期領域では、実際の現在位置は次のとおりだった。依頼文の `3\_` に相当する部分は、実体では `3_` という1つのフォルダ。

```text
G:\マイドライブ\SetagayaGenico\1_音源\3_\00_試聴用\
```

この中にMP3が10個ある。TXT・LRCは存在しなかった。Driveコネクターからのフォルダ名検索は該当なしであり、クラウド側のID・親・権限は移行前にアプリ用の読取接続等で改めて確認する。

### Notion

取得元は、ユーザー指定の[3rdアルバムのページ](https://app.notion.com/p/3rd-1e5605e24ee980c487ddcf8e4104189b?source=copy_link)および関連する楽曲ページ。

- **2026-10-28、ユーザーが追加したSetagayaGenicoアカウントの接続で、指定アルバムページと楽曲ページの取得に成功。** 接続アカウントの本人情報も照合した。今後このデータは同アカウントの接続を明示して取得する。
- アルバム本文は空だが、`songs` プロパティに13件の関連楽曲ページがある。歌詞はその各楽曲ページから取得する。
- 現在の音源10曲すべてに対応するページを取得し、歌詞本文を確認した。対象は `4 Lib Isl`、`anchor`、`flowers3`、`ghost`、`Milkomeda`、`noah`、`ほしを継ぐもの`、`砂`、`紐`、`螺旋とは`。LRCのタイムスタンプはまだない。

- 当初の別アカウントでは指定ページが404だったが、新しい接続によりアクセス上の問題は解消した。別IDの `3rd album 構想` を歌詞の代替データには使わない。

13件の関連楽曲のうち、現行の音源10曲だけを初回移行の対象とする。音源がない楽曲は、歌詞だけで再生できる曲として一覧へ加えない。

## 3. Google Driveの配置案

**既存の `00_試聴用` フォルダそのものを `1_音源` 直下へ移動する。** 同名の新しいルートを作り直さず、既存のDriveフォルダIDを維持する。

```text
G:\マイドライブ\SetagayaGenico\1_音源\
└─ 00_試聴用\                        ← アプリの公開対象ルート
   ├─ 3rd album\                    ← アプリで選ぶフォルダ
   │  ├─ 4 Lib Isl.mp3
   │  ├─ 4 Lib Isl.lrc
   │  ├─ anchor_demo.mp3
   │  ├─ anchor_demo.lrc
   │  ├─ flowers3.mp3
   │  ├─ flowers3.lrc
   │  ├─ ghost.mp3
   │  ├─ ghost.lrc
   │  ├─ milkomeda.mp3
   │  ├─ milkomeda.lrc
   │  ├─ noah.mp3
   │  ├─ noah.lrc
   │  ├─ ほしを継ぐもの.mp3
   │  ├─ ほしを継ぐもの.lrc
   │  ├─ 砂_demo.mp3
   │  ├─ 砂_demo.lrc
   │  ├─ 紐.mp3
   │  ├─ 紐.lrc
   │  ├─ 螺旋とは_demo.mp3
   │  └─ 螺旋とは_demo.lrc
   └─ 別のフォルダ\                 ← 将来追加可能
      ├─ 曲名.mp3
      └─ 曲名.lrc
```

LRCの名前は配置規則の例。Notionに歌詞がない曲には歌詞ファイルを捏造しない。

### 配置・対応付けのルール

- フォルダ内へMP3と歌詞を並べる。1曲につき、拡張子以外を同じ名前にする。
- 現在のMP3のファイル名と中身は変更しない。コピー・再アップロードではなく、同じDriveファイルIDの親を更新して移動する。
- 対応付けには元のファイル名から拡張子だけを除いた名前を使う。表示用の曲名は使わない。例えば現行の表示名変換では `anchor_demo.mp3` が `anchor` になるため、これを照合に使うと誤関連が起こる。
- 同じ名前のLRCを優先し、LRCがなければ同名TXTも読めるようにする。全文用TXTをLRCと二重に作る必要はない。
- 同名の音源・歌詞が複数ある場合は勝手に1つを選ばず、関連付けの問題として表示する。Unicodeの表記揺れを吸収する場合も、候補が一意のときに限る。
- 直下の通常フォルダだけを選択対象にする。初回は任意の階層の再帰探索やDriveショートカットを対象にしない。
- MP3・歌詞は現在と同じアプリ認証の内側で配信する。フォルダごとの利用者権限を分ける機能は今回の対象に含めない。

## 4. 歌詞データの作成・更新

1. 指定のNotionページから関連楽曲を読み、現在のMP310曲との対応表を作る。ページID・曲名・原文取得時点も作業記録へ残す。
2. 歌詞本文だけを取り出し、段落・改行・記載された繰り返しを保ってLRCに変換する。制作メモ・コメント・プロパティを混ぜない。未記入や版の競合は報告し、別の曲の歌詞で埋めない。
3. 初回のタイムスタンプは実音源の長さの範囲に収まるよう仮配置する。歌い出しや行ごとの正確な同期を保証するものではない。
4. 初回のタイムスタンプが仮配置であることと、後日の同期調整・確認履歴は内部作業記録へ残す。未確認の同期精度を確認済みとして扱わない。
5. Driveへ配置後、アプリから取得・解析して本文と行数を照合する。

**初回はNotionからDriveへの取り込み。アプリの利用時にはDriveを参照する。** NotionとDriveの常時双方向同期は作らない。後日の歌詞修正はDriveの同じ歌詞ファイルを更新し、オンラインで一覧・歌詞を更新したときに反映する。

## 5. スマホでの操作

### フォルダ選択と再生

- ライブラリ上部に現在のフォルダ名と切替操作を置く。選択画面で `3rd album` などを選ぶ。
- 最後に選んだフォルダを端末ごとに記憶する。フォルダが1つだけの場合は、その曲一覧を直接開けるようにする。
- **閲覧中のフォルダと再生キューを分ける。** フォルダを見比べても、再生中の曲・再生位置・キューは維持する。
- 別フォルダの曲を再生した時点で、そのフォルダの曲順を次の再生キューにする。ミニプレイヤーから現在の再生画面に戻れる。
- 曲順、検索、保存済み絞り込みは選択フォルダの中に適用する。フォルダ切替時に検索語はリセットする。
- 画面全体のスクロールは増やさず、フォルダ一覧・曲一覧・歌詞領域をそれぞれ必要な範囲でスクロールさせる。

### 歌詞の切替

歌詞画面上部に `追従 / 全文` の切替を常時置く。

| 表示 | 動作 |
| --- | --- |
| 追従 | 再生位置に応じた強調・自動スクロール。行タップでその位置へシーク。手動スクロール後は「再生中の歌詞に戻る」。 |
| 全文 | 時刻を除いて元の段落・改行を保った本文を表示。自動スクロールと行タップによるシークは行わず、自分のペースで確認できる。 |

- 切替で再生を止めたり、再生位置を変えたりしない。
- 初期表示は追従可能な歌詞なら追従とし、以後は端末ごとの表示選択を保持する。
- 全文から追従へ戻ったときは、現在の再生位置に対応する行を表示する。
- 全文のスクロール位置は、その曲を見ている間は保持する。文字サイズは現在の調整を基準にする。
- TXTなどタイムスタンプがない歌詞では全文を表示し、追従は選択不可とする。歌詞未登録、取得中、取得失敗は区別し、音源再生は継続できる。
- LRCの複数時刻タグから追従用の行を展開しても、全文を不自然に重複させない。全文は元データの行順から作る。

## 6. アプリ側の実装

### API・認可

- `GET /api/albums`：設定済みルート直下の通常フォルダを返す。
- `GET /api/list?albumId=...`：そのフォルダの曲一覧と対応歌詞のメタデータを返す。
- 旧クライアントの `GET /api/list`（albumId未指定）には互換規則を設ける。移動前はルート直下の10曲、移動後は移行時に記録した `3rd album` のIDへ解決し、旧画面を再読込しても一覧を空にしない。移行モード終了後も、この既定アルバムへの解決を保つ。
- 既存 `GET/HEAD /api/stream/:audioId`：アルバム内の音源にも対応する。音源URLのID・version形式は維持する。
- `GET /api/lyrics/:audioId`：音源に対応する歌詞をサーバーで解決して返す。クライアントが指定した任意のDrive文書IDを読むAPIにはしない。
- すべてのAPIでセッションを検証する。ファイルの親が許可されたアルバムであり、そのアルバムの親が設定済みルートであることをサーバー側で確認する。削除済みファイル・ショートカット・ルート外のIDは拒否する。
- 歌詞はUTF-8のTXT/LRCに限定し、取得バイト数、文字数、行数を制限する。HTMLとして挿入せずテキストとして表示する。メタデータのMIME表記だけに依存せず、拡張子と本文も検証する。
- 一覧・歌詞・音源は共有CDNに保存させない。認証付きの非公開応答とし、端末への保存はログイン範囲を分けた既存の仕組みで制御する。
- 歌詞の取得は再生開始の待ち条件にしない。小さい一覧メタデータと本文取得を分離し、歌詞画面を開く時や端末保存時に取得する。

### データとオフライン

- `Album` を追加し、曲に `albumId` と歌詞ファイルID・歌詞versionを持たせる。
- 音源versionと歌詞versionを分ける。歌詞の修正だけで音源の再保存を要求しない。
- カタログと曲順は `ログイン範囲 + albumId` ごとに保存する。音源の実体は既存の `ログイン範囲 + 音源ID + 音源version` のまま扱い、同じ曲を重複保存しない。
- 現在の `drive-player.order.${cacheScope}` の曲順は、`3rd album` の新しい曲順へ一度だけ引き継ぐ。移行をやり直しても新しい並び順を上書きしない。
- 選んだ曲の保存時に、曲情報と関連歌詞も保存する。歌詞取得だけ失敗した場合は「音源は保存済み／歌詞は未保存」を区別して再試行できるようにする。
- 保存済みのフォルダ情報・曲一覧・歌詞は圏外でも開ける。未保存の曲は再生不可と分かるようにする。未取得のフォルダ内容を圏外で取得できるとは表示しない。
- 30日のオフライン期限、401・ログアウト時の全フォルダの私有データ削除、別タブへの失効反映を維持する。
- Driveの歌詞を標準表示にする。既存の端末内の手動歌詞は「この端末の歌詞」として別に保全し、明示した時だけ切り替える。無断でDriveへアップロードしない。

## 7. 移行の順番と戻し方

1. **棚卸し**：既存ルート・音源のDrive ID、現在の親、サイズ、checksum、読取権限を記録する。Notionの本文を取得し、音源との対応を確定する。
2. **歌詞の下準備**：ローカルの作業用領域でLRCを作成・解析する。歌詞本文や実音源を公開用リポジトリ、フロントエンドの静的配信領域へ入れない。
3. **互換対応版のプレビュー**：旧ルート直下の音源と新アルバム構成を移行期間中だけ併用できるAPIを用意し、Chromeで確認する。旧一覧を開いたままでも、移動後の同じ音源IDを許可ルート内で解決できるようにする。
4. **互換版を先に反映**：移動前の配置で再生できる状態を確認してからDriveを変更する。
5. **Driveの配置変更**：既存 `00_試聴用` を `1_音源` 直下へ移動し、その中に `3rd album` を作る。10曲を同じIDのまま移動し、歌詞を配置する。移動前後でサービスアカウントが読めること、既存の利用者の必要なアクセスが失われないことを確認する。`1_音源` 全体をアプリへ公開しない。
6. **移動後の検証**：ID・checksum・件数を照合し、一覧、実音源、両歌詞モード、端末保存、圏外再起動を確認する。既存の保存メタデータには `albumId` を補い、音源の実体を消さずに引き継ぐ。
7. **移行モードを終了**：ルート直下音源の互換表示を外し、フォルダ選択の構成に統一する。

既存 `00_試聴用` のIDを保てば、環境変数 `FOLDER_ID` は同じ値でよい。現在のCookie署名にはこの値が含まれるため、同名フォルダの作り直しや不要なID変更を避ける。保存済み音源の継承も検証対象にし、事前に保証はしない。

戻す場合は、記録した親IDに10曲を戻し、旧デプロイへ戻す。旧アプリはルート直下のMP3しか読めないため、**デプロイの巻き戻しだけでは復旧しない**。元の `3_` フォルダも移行確認が終わるまで残す。

## 8. 完了条件

- 複数のフォルダを切り替えられ、閲覧中の切替では再生が止まらない。
- 現在の10曲が同じ音源ID・内容で再生できる。利用者ごとの選択フォルダや曲順が互いに書き換わらない。
- 歌詞をDriveから取得でき、歌詞だけの更新を反映できる。未登録や不一致で別の曲の歌詞を表示しない。
- 追従と全文を何度切り替えても、再生位置と全文の読みやすさを損なわず、端末ごとの表示選択を引き継げる。
- 曲と歌詞の保存後、圏外で起動・再生・シーク・表示切替ができる。旧保存データの互換移行を確認する。
- ルート外のアルバムID・音源ID・歌詞ID、削除済み・重複・不正UTF-8・過大歌詞を拒否し、Range/HEAD、401、ログアウト、30日期限の既存要件も通る。
- Node.js 24でlint・型検査・buildと必要な回帰テストを通し、Chromeのスマホ幅で確認する。iPhone Safari／Android実機の確認項目は別途残す。

**指定Notionページへのアクセスは解消済み。** 次の実装段階では、原文の未記入箇所と複数の本文候補を整理したうえで歌詞データを作成する。現在は接続・原文の確認までで、LRC作成・Drive配置・アプリ実装・本番反映は未実施。
