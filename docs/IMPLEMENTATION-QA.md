# 実装の確認記録

2026-10-28 / Node.js 24.22.1 / Chrome

## 確認した動作

- 新UIのログイン→曲一覧→再生画面→歌詞登録・表示。
- フロントエンドのタイマーではなく、実際のaudio要素で再生位置が進むこと。
- 完全取得した音源だけを保存済みに表示し、音源のversionが変わると旧保存を新しい保存と誤認しないこと。
- 時刻付きLRCを端末に保存し、歌詞の行タップで5秒位置から実音源が再生されること。
- 曲末尾から次の曲へ連続再生し、最後の曲で停止すること。
- 検証サーバーを停止後、ページを再読み込みしても保存したシェル・一覧・歌詞が開き、保存曲を再生・シークできること。
- サーバーを停止したままログアウトし、再生終了・音源と歌詞の削除・ログイン画面への遷移が完了すること。

ローカル検証は本番コードをビルドし、Driveの外部通信だけをテストデータへ置き換えたlocalhost:4177で実行。テスト用MP3と歌詞は実際の楽曲ではない。

## 品質確認

- ESLint、TypeScript、Vite buildを実行。
- 認証・CSRF・フォルダ制限・Range/HEAD・ストリーミング、SW・許可期限・保存取消、歌詞パーサーとIndexedDBの実行テストを実施。
- 独立レビューで発見したCacheStorage拒否／容量不足時のオンライン利用失敗と、localStorage拒否時の1分後停止を修正し、回帰テストを追加。
- SW準備／返信待ちの上限と取消を確認。時刻巻戻し・401・logout・別タブの清算もテスト。
- 旧音源の切替後に到着する古いerror eventは、現在のMediaErrorがnullなら無視する。
- パッケージ監査で本番依存の既知脆弱性0件。

## 残る実機確認

PC Chromeでのスマホ幅表示・実音源API確認と、iPhone Safari／Android実機のOSバックグラウンド動作は区別する。後者はこのPCだけでは検証できない。ブラウザの保存領域を永久保持する保証は行わない。
